## 一、研究結論（先講重點）

| 層級 | 對「負數金額統一發票」的立場 | 法源 |
|---|---|---|
| **法律層級**（營業稅法）| **未明文禁止** | 加值型及非加值型營業稅法 §32 全文未提及金額正負 |
| **法規命令層級**（統一發票使用辦法）| **未明文禁止，但整套機制設計繞過負數**：退款一律走「作廢」或「折讓單」 | §20、§20-1、§24 |
| **法規命令層級**（統一發票給獎辦法）| **承認其存在**，但排除中獎資格 | §11 第 1 款 |
| **行政指導層級**（財政部國稅局函釋 / 宣導）| **建議不要開立** | 財政部臺灣省中區國稅局等多次宣導 |

**綜合結論**：

> 法規**沒有禁止開立金額為負數的統一發票**，但整套使用辦法的退款機制（作廢 + 折讓單）設計上根本**不需要負數發票**這個工具。行政機關進一步以「行政指導」方式建議不要開立，理由是避免消費者誤拿去對獎。實務上正規營業人應**走作廢/折讓單路徑**，不主動開立負數發票。

→ 對 POS / 發票系統設計而言：**走折讓單路線（含同期作廢路線），發票主表的金額欄位使用 UNSIGNED（資料庫層強制不允許負數）**。

## 二、法律層級：《加值型及非加值型營業稅法》§32

### 條文全文（精簡逐段）

> 第三十二條（中華民國 99 年 12 月 8 日修正版本）
>
> 1. **營業人銷售貨物或勞務**，應依本法營業人開立銷售憑證時限表規定之時限，**開立統一發票交付買受人**。但營業性質特殊之營業人及小規模營業人，得掣發普通收據，免用統一發票。
> 2. 營業人對於應稅貨物或勞務之**定價，應內含營業稅**。
> 3. 營業人依第十四條規定計算之**銷項稅額**，買受人為營業人者，應與銷售額於統一發票上分別載明之；買受人為非營業人者，應以定價開立統一發票。
> 4. 統一發票，由政府印製發售，或核定營業人自行印製，或由營業人**以網際網路或其他電子方式開立、傳輸或接收**；其格式、記載事項與使用辦法，由財政部定之。
> 5. 主管稽徵機關得核定營業人使用收銀機開立發票或以機器收據替代之。

### 對「負數金額」的處理

**無提及**。§32 全文未出現「負數」、「正數」、「沖銷」、「負額」等字眼。
- 條文只規範「應於何時開立、由誰開立、開立格式由誰訂」
- 金額正負問題下放給《統一發票使用辦法》與相關函釋處理

### 附帶研判：附帶的「銷售憑證時限表」

§32 第 1 項提到「**營業人開立銷售憑證時限表**」（附於營業稅法之附表），規範各業別何時應開立統一發票，例如買賣業為「發貨時」、勞務承攬業為「收款時」等。其中亦含「**發貨前已預收的貨款，應於收款時先行開立統一發票**」之預收貨款規定。**該時限表規範的是「開立時點」，不是金額正負**。

## 三、法規命令層級：《統一發票使用辦法》

關鍵條文：第 20 條（紙本退回折讓）、第 20-1 條（電子發票退回折讓）、第 24 條（記載錯誤作廢重開）。

### 3-1. 第 20 條（紙本發票銷貨退回 / 折讓）

> 營業人銷售貨物或勞務，於開立統一發票後，發生銷貨退回、掉換貨物或折讓等情事，應於事實發生時，分別依下列各款規定辦理；其為掉換貨物者，應按掉換貨物之金額，**另行開立統一發票**交付買受人。
>
> 一、買受人為營業人者：
> （一）開立統一發票之銷售額**尚未申報者**，應收回原開立統一發票收執聯及扣抵聯，黏貼於原統一發票存根聯上，並**註明「作廢」字樣**。但原統一發票載有買受人之名稱及統一編號者，得以買受人出具之**銷貨退回、進貨退出或折讓證明單**代之。
> （二）開立統一發票之銷售額**已申報者**，應取得買受人出具之銷貨退回、進貨退出或折讓證明單。但以原統一發票載有買受人之名稱、統一編號者為限。
>
> 二、買受人為非營業人者：
> （一）開立統一發票之銷售額**尚未申報者**，應收回原開立統一發票收執聯，黏貼於原統一發票存根聯上，並**註明「作廢」字樣**。
> （二）開立統一發票之銷售額**已申報者**，除應取得買受人出具之銷貨退回、進貨退出或折讓證明單外，並應收回原開立統一發票收執聯。如收執聯無法收回，得以收執聯影本替代。但雙方訂有買賣合約，且原開立統一發票載有買受人名稱及地址者，可免收回原開立統一發票收執聯。
>
> 前項銷貨退回、進貨退出或折讓證明單**一式四聯**，第一聯及第二聯由銷售貨物或勞務之營業人，作為申報扣減**銷項稅額**及記帳之憑證，第三聯及第四聯由買受人留存，作為申報扣減**進項稅額**及記帳之憑證。

### 3-2. 第 20-1 條（電子發票銷貨退回 / 折讓）

> 營業人銷售貨物或勞務，於開立電子發票後，經買賣雙方合意銷貨退回或折讓、進貨退出或折讓，應**以網際網路或其他電子方式開立、傳輸或接收銷貨退回、進貨退出或折讓證明單**，其應有**存根檔、收執檔及存證檔**，用途如下：
>
> 一、**存根檔**：由賣方營業人自行保存，作為記帳憑證及依本法規定申報扣減銷項稅額之用。
> 二、**收執檔**：交付買受人收執，其為營業人者，作為記帳憑證及依本法規定申報扣減進項稅額之用。
> 三、**存證檔**：由賣方營業人傳輸至平台存證。

### 3-3. 第 24 條（記載錯誤）

> 營業人開立統一發票有第九條第一項規定應記載事項記載錯誤情事者，應**另行開立**。
> 前項情形，該誤寫之統一發票收執聯及扣抵聯**註明「作廢」字樣**，黏貼於存根聯上，如為電子發票，已列印之電子發票證明聯應收回註明「作廢」字樣，並均應於當期之統一發票明細表註明。

### 3-4. 對「負數金額」的處理

**全辦法皆未提及「負數」字眼**，也未授權或禁止開立負數發票。但設計上：

| 業務情境 | 法定處理 | 是否需要負數發票？ |
|---|---|---|
| 同期、未申報、整筆退 | 作廢原發票 | ❌ |
| 同期、已申報，整筆 / 部份退 | 折讓證明單（電子發票走 §20-1）| ❌ |
| 跨期退 | 折讓證明單（電子發票走 §20-1）| ❌ |
| 部份折讓 | 折讓證明單 | ❌ |
| 原發票記載錯誤（金額、品項、買方）| 作廢重開 | ❌ |

→ **使用辦法已用「作廢 + 折讓單」兩套機制涵蓋所有退款場景，根本不需要負數發票**。這也是為什麼國稅局可以理直氣壯地說「請勿開立負數發票」— 從法規架構上看，沒有必要開。

### 3-5. 折讓單≠負數發票

折讓單在稅務申報上的角色是「**從銷項稅額/進項稅額中扣減**」（§20 第 2 項明文）。它是一張獨立稅務憑證，**有自己的單號、格式、傳輸機制**，不是負數金額的統一發票。

- 統一發票：銷售發生 → 加項
- 折讓證明單：退貨折讓發生 → 減項

**兩種憑證並列存在於申報書中**，加減互抵後得銷項稅額/進項稅額。

## 四、《統一發票給獎辦法》§11 — 反證負數發票存在

### 條文全文

> 第十一條
>
> 統一發票有下列各款情形之一，**不適用本辦法給獎之規定**：
>
> 一、**無金額，或金額載明為零或負數者**。
> 二、未依規定載明金額或金額不符或未加蓋開立發票之營利事業統一發票專用印章者。
> 三、破損不全或填載模糊不清、無法辨認者。但經開立發票之營利事業證明其收執聯與存根聯所記載事項確屬相符經查明無訛者，不在此限。
> 四、載明之買受人經塗改者。
> 五、已註明作廢者。
> 六、依各法律規定營業稅稅率為零者。
> 七、依規定按日彙開者。
> 八、漏開短開統一發票經查獲後補開者。
> 九、買受人為政府機關、公營事業、公立學校、部隊及營業人者。
> 十、逾規定領獎期限未經領取獎金者。
> 十一、適用外籍旅客購買特定貨物申請退還營業稅實施辦法規定申請退稅者。
>
> 公用事業掣發載有載具識別資訊之兌獎聯有破損不全或填載模糊不清，致無法辨認載具識別資訊情形者，不適用本辦法給獎規定。

### 條文的反證效力

§11 第 1 款明文排除「金額為零或負數」的中獎資格。從立法邏輯反推：

- 若負數發票一律被禁止開立或根本不存在，此款為冗文，立法者無須特別排除
- 立法者把它列入「不適用給獎」清單，等同**默認其存在的可能性**
- 但給獎辦法的角色是「**處理已存在憑證的兌獎資格**」，不是「**規範何種憑證可開立**」 — 後者是《使用辦法》的角色

→ **§11 不構成「允許開立」的授權，但也未構成「禁止開立」的禁令**。它處理的是「**若不慎開立 / 因故開立**」的下游效應。

### 為什麼實務上會出現負數發票

歷史與現實場景（推測，非完整清單）：
- 電子發票普及前、紙本時代部份 POS 系統的偷懶做法（直接負數沖原發票）
- 折讓單機制未普及前的小規模營業人變通
- 申報當期內、部份退貨且原發票買受人為非營業人時，某些業者選擇直接「再開一張負數發票沖原票」而非走折讓單流程
- 系統 bug 或人為誤操作（負數誤入金額欄位）

立法者選擇用《給獎辦法》§11 排除這類發票的兌獎資格，**間接導引業者不要開立**（因為消費者拿到也沒用、會抱怨），而非用《使用辦法》直接禁止。這是**行政上「以結果反推行為」的設計**。

## 五、行政指導層級：財政部國稅局宣導

財政部多個區國稅局**橫跨多年**重複宣導同一立場，無單一函釋編號，屬新聞稿性質的行政宣導。

### 5-1. 三份可考的宣導文本

| 來源（民間轉載）| 引用單位 | 發文時期 | 措辭 |
|---|---|---|---|
| [台灣法律網 #387662](https://www.lawtw.com/archives/387662) | 財政部臺灣省中區國稅局**北港稽徵所** | 2010-06-01 | 「請勿開立金額為零或負數之統一發票」 |
| [台灣法律網 #454240](https://www.lawtw.com/archives/454240) | 財政部中區國稅局**沙鹿稽徵所** | 2018 | 「請勿開立無金額，或金額為零或負數之統一發票」 |
| [SERP 會計事務所 qa01030](https://www.serp.com.tw/qa01030.htm) | 財政部**臺北市國稅局** | （未標日期）| 「請勿開立金額為零或負數之統一發票」 |

橫跨 8 年、三個不同稽徵單位、措辭幾乎完全一致，可判定為**財政部對下級稽徵所的標準宣導模板**。但**全部都沒有引用具體的函釋字號**（如「台財稅字第○○○○○○○○○○號函」），顯示這不是有法律地位的解釋函令，是新聞稿性質的政令宣導。

### 5-2. 宣導的法源論述（lawtw #387662 完整版）

> 該所進一步說明，**依加值型及非加值型營業稅法第 32 條第 1 項規定，營業人銷售貨物或勞務，應依法開立統一發票交付買受人**。因此，營業人代收稅款、電信費用、信用卡費、水電費、路邊停車費及其他符合代收代付之規定，及信用卡點數兌換商品，或持空瓶退還押瓶費等，營業人與民眾間僅有兌換或退費行為，並無銷售貨物或勞務，**應免開立統一發票**。
>
> 部分營業人誤開立金額為零或負數之統一發票交付民眾，於中獎後，無法依統一發票給獎辦法兌領獎金，造成爭議。
>
> 該所指出，營業人發行商品禮券，應於出售禮券時開立統一發票，民眾持該商品禮券兌換商品時，因該筆交易先前已發生並開立發票，營業人無需再開立金額為零之統一發票。

**論述結構解析**：

1. **正面命題**：§32 規定「**有銷售才開立**」（觸發條件是「銷售貨物或勞務」）
2. **反向推論**：無銷售就**不該開立**任何金額之發票（包含零元、負數）
3. **典型案例**：代收代付、押瓶費、禮券兌換等「非銷售」情境
4. **下游後果**：誤開的零元/負數發票若中獎將造成兌獎爭議

**重要：此論述只覆蓋「無銷售卻開立」情境**，並未直接禁止「有銷售但金額為負」（如部份退貨直接負數沖銷）的情境。後者交由《使用辦法》§20 / §20-1 的「作廢 / 折讓單」機制處理。

### 5-3. 性質判定

| 面向 | 判定 |
|---|---|
| 法律依據 | **間接引用 §32**（無「銷售」即無發票義務的反推），無直接禁止條款 |
| 約束力 | 無強制力 — 違反此宣導本身不會被裁罰 |
| 函釋字號 | **無**（新聞稿性質，非解釋函令）|
| 適用對象 | 廣泛宣導，非特定對象 |
| 目的 | **保護消費者**（避免中獎卻無法兌換），同時降低稽徵端爭議處理成本 |
| 性質 | 倡議式行政指導 / 政令宣導 |

> 措辭用「**請勿**」是建議語，非「**不得**」、「**應不得**」之禁止語。比較《使用辦法》§20「**應**收回原統一發票收執聯」— 那才是法規拘束力的措辭。

### 5-4. 為什麼仍應遵守

雖無法律強制力，但對營業人而言**遵守此宣導有實質利益**：

- 避免消費者投訴與商譽損失
- 避免財政部稽徵端以「**異常開立發票**」為由列入查核名單
- 避免兌獎爭議與後續處理人力成本
- 對齊行業常規（連鎖大店、上市公司皆不主動開負數發票）
- 符合 §20 / §20-1 的「作廢 / 折讓單」標準作業流程

## 六、為什麼禮券發票案例值得提及

財政部對「**禮券銷售與兌換**」有明確函釋：

> 營業人發行商品禮券時，應於**禮券銷售時**開立統一發票（金額 = 禮券面額）。
> 消費者持禮券兌換商品時，因交易已於禮券銷售階段完成、發票已開，**毋須再開立一張零元發票**。

這個案例強化了財政部的立場：

- 「零元 / 負數發票」原則上是**不正常的金流憑證**
- 凡是有對應的正規憑證流程的（如禮券銷售時即開），就走那條路
- 不要為了「對應每一個事件」而硬開零元/負數發票

對 POS 系統的啟示：**每一張發票都應對應到一筆實質金流交易**，不要為了帳目對齊或介面工整而開立金額為 0 或負的發票。

---

## 七、退款的正規路徑（依《使用辦法》§20 / §20-1 落地）

營業人/POS 系統的**退款流程**應依下列分支處理：

```
退款事件發生
    │
    ├─ 同稅期 + 未申報 + 整筆退？
    │     └─ YES → 作廢原發票
    │             - 紙本：收回收執聯（+ 扣抵聯如有），黏貼於存根聯，註明「作廢」
    │             - 電子：呼叫 Giveme cancel API
    │
    └─ 否則（同期已申報 / 跨期 / 部份退 / 金額調整）
          └─ 開立折讓證明單
                  - 紙本：開立一式四聯
                  - 電子：呼叫 Giveme allowance API（產生存根檔/收執檔/存證檔）
```

### 對應到資訊系統設計

| 法規路徑 | 系統建議動作 |
|---|---|
| 作廢原發票 | 將原發票狀態標記為 `voided`，呼叫電子發票加值中心 cancel API |
| 折讓證明單 | 開立獨立的折讓單記錄（與發票分表），呼叫加值中心 allowance API |

**對 schema 設計而言不需要**：
- 在發票表的金額欄位開放負數
- 在發票表加 `subtype` 區分正常 / 負數發票

## 八、對 POS / 發票系統的建議

以下為一般性建議，可作為 POS 或開立發票系統設計時的參考。

### 8-1. Schema 建議

```sql
-- 發票主表 total 維持 DECIMAL UNSIGNED（正數），不開放負數發票
-- 退款 / 折讓資訊另設獨立表

-- 折讓證明單表（表名與欄位為示意）
CREATE TABLE invoice_allowances (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  invoice_id BIGINT UNSIGNED NOT NULL    COMMENT '沖抵哪張原發票',
  allowance_number VARCHAR(50) NOT NULL  COMMENT '折讓單號（電子發票加值中心取得）',
  allowance_date DATETIME NOT NULL,
  amount DECIMAL(10,2) UNSIGNED NOT NULL COMMENT '折讓金額（正數；意義上為沖銷）',
  tax_amount DECIMAL(10,2) UNSIGNED NOT NULL,
  net_amount DECIMAL(10,2) UNSIGNED NOT NULL,
  reason TEXT,
  status ENUM('pending','issued','voided') NOT NULL DEFAULT 'pending',
  api_request_data JSON,
  api_response_data JSON,
  created_by BIGINT UNSIGNED,
  created_at TIMESTAMP,
  updated_by BIGINT UNSIGNED,
  updated_at TIMESTAMP,
  FOREIGN KEY (invoice_id) REFERENCES invoices(id)
);
```

> 表名 / 欄位名為示意，實際命名依各系統慣例調整。

### 8-2. 開立規則

| 退款情境 | 應走流程 | 法源 |
|---|---|---|
| 同稅期 + 全額退 | 作廢原發票 | 使用辦法 §20 第 1 項第 1/2 款 |
| 同稅期 + 部份退 | 折讓證明單 | 使用辦法 §20 第 1 項 + §20-1 |
| 跨稅期 + 任何退款 | 折讓證明單 | 同上 |
| 原發票金額 / 品項錯誤（非退款）| 作廢重開 | 使用辦法 §24 |

### 8-3. 系統明文不支援開立負數發票

在發票 Model / Request validation 加上金額下限：

```php
'total' => ['required', 'numeric', 'min:0.01'],  // 不允許 ≤ 0
```

並在系統的發票模組說明文件中明文記載：

> 不開立金額為 0 或負數之統一發票。
> 退款需求一律走「作廢」（同期全退）或「折讓單」（部份退 / 跨期退）兩條路徑。
> 法源依據：統一發票使用辦法 §20、§20-1；行政指導：財政部臺北市國稅局、中區國稅局等多年宣導。

## 九、整合表：四種退款情境的完整對應

| # | 情境 | 法規路徑 | 金流端 | 發票端 |
|---|---|---|---|---|
| 1 | 同稅期、紙本可收回、全額退 | 作廢原發票（§20）| 信用卡刷退 / 現金退 | 原發票標記 `voided`；同步寫退款金流記錄 |
| 2 | 同稅期、部份退（紙本 / 電子皆然）| 折讓單（§20、§20-1）| 信用卡刷退 / 現金退 | 新增折讓單並關聯原發票；同步寫退款金流記錄 |
| 3 | 跨稅期、任何退款 | 折讓單（§20-1）| 信用卡刷退 / 現金退 | 同 2 |
| 4 | 原發票記載錯誤（無退款）| 作廢重開（§24）| 無金流 | 原發票標記 `voided` + 新開一張發票；**不寫退款金流記錄** |

> 注意 #4：**只是發票憑證的修正**，沒有實際金流發生，退款金流記錄不動。設計付款 / 退款資料表時須區分「**憑證修正**」與「**真實退款**」是兩個不同事件。

## 十一、結論回顧

本檔為**法規考據型研究**。主要結論：

1. **法律與法規命令層級皆未明文禁止負數統一發票**，但《統一發票使用辦法》§20 / §20-1 / §24 已用「作廢」與「折讓證明單」兩套機制涵蓋所有退款情境，**負數發票在法規架構中無存在必要**。
2. **《統一發票給獎辦法》§11** 的存在反證實務上確實會出現負數金額之統一發票（否則不需排除其中獎資格），但給獎辦法只處理「已開立發票」的下游兌獎效果，**不構成開立授權，也不構成禁令**。
3. **行政指導**（多個國稅局橫跨多年宣導）建議「請勿開立」零元或負數發票，措辭為建議語非禁止語，無強制力，但遵守有實質利益。
4. **建議 POS / 發票系統**：發票表金額欄位維持 UNSIGNED 不開放負數；退款一律走「作廢」（同期全退）或「折讓單」（部份退、跨期退）；折讓單建議獨立成表，結構與發票並列。
